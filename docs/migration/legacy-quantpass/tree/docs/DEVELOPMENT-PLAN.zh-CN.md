# QuantPass 单人顺序开发计划

版本：1.0，2026-09-05

性质：工程任务拆分，不是新产品决策、已实现功能或生产审批。

入口：[个人 TODO](../TODO.md)；产品依据：[决策登记](PRODUCT-DECISIONS.zh-CN.md)。

## 执行方法与架构边界

1. 每次仅有一个模块或子任务进行中。模块按 M00 → M16 顺序推进；子任务编号保持稳定，便于后续直接说“开发 M02.03”。
2. 全部开发任务的责任人都是项目开发者本人。普通任务自测后记录证据；资金、密码学和保密边界的生产验收还需要独立审核。
3. 子任务以约半天到两天专注工作为拆分目标，不是工期承诺。若开始后发现范围过大，拆为 `.a/.b`；先完成 M00–M03 后再用实际速度估算后续，当前不虚构总交付日期。
4. 每个模块都包含实现、测试、说明及可运行结果。不要先完成所有后端，再一次性补前端与测试；M03 就开始使用最小页面，后续沿用并逐步接入真实能力。
5. 推荐先采用一个仓库、一个 Web 应用、一个模块化 API/后台任务应用及一个主要业务数据库。Indexer、Keeper、Performance 先作为清晰隔离的逻辑模块，不默认分别部署成独立微服务。具体框架在 M01 记录选择，不在本次安装。
6. **安全隔离不能因单人开发而取消。** 不受信策略执行必须在独立、受限运行环境；它不能在持有 API/数据库/用户权限的进程中直接执行。生产保密运行环境及其密钥域独立，不能用“模块化单体”合并掉。
7. 应用目录按需建立：`apps/web`、`apps/server`、`packages/domain`、`packages/contracts`、`packages/sdk`、`runtime`、`infra`。按用户要求已建立 [modules/M00–M16 工作入口](../modules/README.md)，用于模块专用交付物与导航，不代表创建了全部应用或微服务，也不重写现有原型。
8. 模拟 token、venue、签名者、费用和容量参数只能出现在显式测试配置中。缺少生产必需配置时拒绝启动/发布，禁止自动回退模拟实现。

各模块列出的文件位置是实施时拟创建的交付物，不表示它们现在已经存在。证据统一写入 `docs/evidence/Mxx.md`，包括运行命令、版本/提交、场景结果、剩余限制和审核记录。

## 当前代码基线

本次检查发现一个 TypeScript reference core：`src/security-model/index.ts`，测试为 `test/security-model.test.ts`。在本地 Node v24.12.0 执行 `npm test`，6/6 通过。代码使用 Ed25519、SHA-256、内存防重放存储以及旧的 CEX/加密资产样例，不等于 EVM 合约、链上资产控制或生产 TEE 已完成。

优先复用其负向测试思路和固定精度金额方法；不能将 `MemoryReplayStore`、样例签名或旧交易场所配置直接带入生产。

## M02 — SaaS 额度与资金领域模型

前置：M01。规模：中。目标：先把资金含义写对，不接钱包或真实链。

- [x] M02.01 在 `packages/domain` 定义整数金额、资产精度、SaaS 额度及状态转换，固定“1 Pass = 1 USDT 运行额度”，不绑定 Pass 市场价格。

## M05 — 策略登记与 Pass 合约

前置：M04；正式 schema 受 D1/D2/D4 约束。规模：中。目标：本地链上的使用权身份，不带真实销售资金。

- [ ] M05.01 建立 Solidity 工程、测试部署与共享 SDK；设计 Registry 对象、artifact/model/config commitment 及角色，避免把旧升级权限直接搬入不可变策略。
- [ ] M05.02 在标准和供应规则确认后实现 Pass；未确认时仅写测试接口与通用测试，不能默认选 ERC-20/1155 或发行 80% 容量。
- [ ] M05.03 实现绑定、解除、冷却、FREE 转让及唯一占用，定义旧授权失效 epoch；处理可拆分代币时必须有明确数量锁定模型。
- [ ] M05.04 做 ownership、越权铸造、重复绑定、转让竞态、撤销后同策略重绑与历史不可重置测试；给事件写可索引 schema。

验收：本地测试链可完整重放 Pass 生命周期，不能转移已占用额度或复活旧授权。此时不是正式发行模块；D1/D2 未决不能把测试供应上限当生产上限。

<a id="m06"></a>
## M06 — 用户 Vault 与链上风险控制

前置：M05；正式额度/退出规则受 D2/D3/D5 约束。规模：大，按子任务逐个验收。目标：资金权限真正由合约约束。

- [ ] M06.01 实现 Vault/Factory 的存款、额度分配、闲置提款、撤销与待结算状态，按 M02 样例验证链上账本；不授予策略任意 call/delegatecall/提款权限。
- [ ] M06.02 实现 EIP-712 签名与 nonce/epoch。domain 使用标准字段；Vault、nonce、deadline 等绑定在 typed message，不能将其当私有 domain 字段。兼容 EOA/ERC-1271 并建立 SDK/Solidity 测试向量。
- [ ] M06.03 接 mock Adapter，验证资产/venue/receiver、价格、敞口、滑点、频率、累计预算、费用及实际执行前后余额；异步结算预留风险，不能仅靠交易前模拟。
- [ ] M06.04 定义暂停/撤销/价格失效/持仓未结算下的 owner 操作矩阵；配置版本不能被管理员静默替换扩大旧授权。用 fuzz/invariant 测试重入、越权、重复执行及退出路径。

验收：策略无法消费闲置余额；Builder/平台无法任意提取本金；旧 Intent、恶意 Adapter 和失效授权被拒绝。无效外部条件下不能承诺即时清仓，但用户权利不被管理员任意撤销。

签名边界依据 [EIP-712 标准](https://eips.ethereum.org/EIPS/eip-712)：标准不自带防重放，必须由协议处理。本项修正旧清单将 nonce/deadline 放入 domain 的错误表述。

<a id="m09"></a>
## M09 — 保密运行与不可变发布

前置：M08、M04；D4 必须确认。规模：大。目标：把验证过的保密方案接入真实执行链路。

- [ ] M09.01 实现 Builder 本地打包、依赖锁定、manifest 签名、artifact 加密；扫描与审查必须在明确的信任边界中发生，不能要求普通 API 解密私有策略。
- [ ] M09.02 实现 attestation 验证、加载后 artifact/model/config 完整性校验、签名者授权与链上 Registry 绑定；拒绝 debug、过期、错误 measurement 及未授权版本。
- [ ] M09.03 实现受限固定模型推理、数据入口、输出最小化、任务隔离、资源限额、加密状态检查点及防旧状态复活；首版不支持训练或外部模型替换。
- [ ] M09.04 完成密钥轮换/撤销、管理员权限与网络边界验证，将受限 Intent 接入 M08；测试宿主失陷、替换模型、KMS policy 变动、重启、错误日志泄密和重复实例出单。

验收：可说明“谁仍被信任、谁不能读明文、谁能改解密规则”；正确受验证环境能运行，错误环境不能取得相关权限。普通服务器不得因性能或调试原因回退到明文执行。不能以 TEE 标签代替端到端验证。

## M10 — Builder 发布及首次销售

前置：M09；D1/D2/D4 与发行价格/销售方式须确认。规模：中。目标：将底层能力做成 Builder 可用的测试网流程。

- [ ] M10.01 在现有 API/Web 加入钱包 challenge、会话、对象权限、限流和 Builder 页面；不把登录当作所有交易的授权。
- [ ] M10.02 实现加密上传、发布前验证、容量与提成规则披露、manifest 预览和签名；只展示已允许 Builder 自定义的字段，不默认开放发行量/永久期限/任意收费编辑。
- [ ] M10.03 在销售机制批准后，实现支付与 Pass 交付的原子结算、失败退款、取消/过期以及费用上限；测试资金与生产资金隔离。
- [ ] M10.04 E2E 验证发布、错误 artifact、重复提交、买入失败与重复结算；页面明确未审计、模拟/测试网和未定规则，不把固定策略显示成可自由升级。

验收：自有 Builder 可从页面完成一次不可变策略发布及测试销售，消费者付款与 Pass 到账能对账。无定价/容量规则时只展示 mock，不能宣称发行模块完成。

<a id="m11"></a>
## M11 — Consumer 完整使用流程

前置：M10。规模：中。目标：把 M03 演示页升级为可实际测试的产品流程。

- [ ] M11.01 实现钱包/网络检查、Pass 查询、买入、Vault 创建和绑定，签名前显示网络、合约、额度、资产、费用及撤销方法。
- [ ] M11.02 实现存款与资金分配，分开展示运行额度、运行资产、闲置余额、订单预留和可提取金额；多存不自动授权策略使用，多存也不自动补亏损。
- [ ] M11.03 实现运行/暂停/停止、独立闲置提款和待结算退出；提供不依赖主前端/平台 Keeper 的可验证 owner 调用说明，不在停链时显示提款已到账。
- [ ] M11.04 实现 pending/finalized/reorg/失败恢复状态、移动端与键盘基本可用性；找真实试用者完成指定任务，记录错误与理解偏差并修正。

验收：用户能购买、存入超额资金、按额度运行、提取闲置及停止退出；不把 SaaS 代币当 ETF，也不把浮盈当可提现现金。指定测试场景全部成功，不能用“用户永远不会误解”代替实际验证。

<a id="m12"></a>
## M12 — 业绩与收益提成

前置：M11；D5 必须确认。规模：大。目标：真实、可复算的策略业绩与费用闭环。

- [ ] M12.01 先冻结会计规范：单位净值/现金流调整方法、时区、估值、gross/net、缺价与更正、HWM 与资金进出/迁移规则。Reference Vault 尚未批准时保留测量源接口，不直接定为唯一来源。
- [ ] M12.02 实现成交/费用/公司行动账本、日周月年业绩和不可选择性重置的历史；覆盖策略停运、亏损记录、资产价格修正与重组。
- [ ] M12.03 实现同一笔总绩效提成在 Builder/平台之间拆分，租金独立；定义链上或混合结算的证据与权限，禁止双重扣费。以 100/20/15/5 作测试时明确仅为 fixture。
- [ ] M12.04 实现公共策略表现、用户个人账单、执行质量和 Pass 价格四类展示；按期间曾启用者统计执行质量，未启用不记零收益、退出者历史不删除，验证参考实例与用户执行差异。

验收：独立计算器可重算账本；纯入金不产生收益，纯提现不产生亏损，费用守恒且不超授权；无法验证的历史明确标记，而不是输出漂亮曲线。上线前公开业绩来源、公平调度与宣传范围须获确认。

<a id="m13"></a>
## M13 — 租费与备用保障

前置：M12；D6 对相应部分生效。规模：中。目标：让发行者正常付费并可追踪服务状态。

- [ ] M13.01 定义资源计量、账单及付款凭证，正常由发行者钱包支付；不默认无限自动扣款，不从消费者本金/闲置余额收租。
- [ ] M13.02 将租费与绩效提成分账，处理多付、少付、重复付款、确认深度、退款与对账；账单应能对应具体资源和服务周期。
- [ ] M13.03 实现租期、到期提醒、异常通知、Builder 收支页及最小运营后台；通知渠道与费用先确认，不实际向全市场群发测试消息。
- [ ] M13.04 在备用资产和触发规则批准后实现 backup 锁定、启用、补足与返还；与容量缓冲及 Builder commitment 严格分开。补齐欠费时既有仓位、退出权与运行服务的状态测试。

验收：正常钱包付款和账单可对账，租金失败不会直接冻结用户资金；备用规则未定则相关功能保持关闭且模块不算全部完成。租赁收益不自动证明足以永久运行。

<a id="m14"></a>
## M14 — Pass 二级市场与做市工具

前置：M13；市场模式、token 标准、费用及合规范围须确认。规模：大。目标：交易的是 SaaS 额度，不是运行中的资产份额。

- [ ] M14.01 选择首版单一市场模式并说明复用/自建边界；只实现批准模式，不同时建设 order book、AMM 和混合市场。
- [ ] M14.02 实现挂单/报价、成交、取消/过期、支付和 Pass 转移原子性、费用与退款；拒绝已 BOUND/COOLDOWN 的数量，处理旧卖单与绑定竞态。
- [ ] M14.03 接入市场页面、深度/价差/历史、交易影响及手续费展示；royalty 若未规定强制路径，不能把信息接口支持当作可靠收款。
- [ ] M14.04 实现最小做市库存/成本/风险面板及自成交、异常成交监控；MM key、运营权限和资金分账，不能让做市库存影响业绩或排序计算。

验收：两名测试用户完成买卖并逐笔对账；重复成交/支付失败/转移竞态不能丢款或双花。高级做市机器人与复杂 LP 策略不是本模块前提，且未授权不得自动投入真实资金。

<a id="m15"></a>
## M15 — 竞价接续与回购结束

前置：M14；D4/D6/D7/D9 按功能分别确认。规模：大。目标：永久使用权对应可解释的接续与结束路径。

- [ ] M15.01 固定接续触发、公告期、补缴、竞价资格/保证金、成交与退款、竞价款去向及无人接手规则；公告可追踪，但不承诺所有用户实际收到。
- [ ] M15.02 实现原子交接：接手者承担租费并承接后续分成，旧角色权限失效；不能修改策略、单方提费或取得用户资金。源码访问按已批准的保护机制处理，不默认交付明文。
- [ ] M15.03 回购定价仍由用户保留待处理：规则未决只定义关闭的接口和状态；确认后再实现购买范围、持有人同意、未回购者权利、仓位/费用结清及结束条件。
- [ ] M15.04 测试无人竞价、原发行者末刻补缴、竞价失败退款、双重交接、收益切换、回购未完成和有活跃仓位时错误停服；历史不能因接续重置。

验收：正常与失败接续可演示，用户资产和权限边界不被交接破坏。D7 未解决不视为回购功能完成；不因想上线而默默删除回购承诺或制造默认回购价。

<a id="m16"></a>
## M16 — 生产准备与独立验收

前置：M15 及本次发布必需决策全部确认。规模：大且含外部依赖。目标：形成可审批发布包，不是自动部署主网。

- [ ] M16.01 固定首发范围与可量测目标：策略数、活跃 Vault、频率、延迟、资源/Gas 成本、故障恢复 RTO/RPO、值守与报警；压测、长稳测试和资源限额有实测报告。
- [ ] M16.02 完成 IaC、环境/密钥分离、构建 digest、最小权限、备份恢复、资产/费用/容量对账和事故演练；单人不可假称具备全天候团队，值守缺口要有可执行的服务边界。
- [ ] M16.03 完成独立合约/基础设施/保密边界审查及修复复测；法律人员按实际地区、发行、自动执行和收费范围确认准入，核验“底层权限”是否足够，不能用免责声明代替。
- [ ] M16.04 形成测试网与生产配置差异、发布资金上限、审计范围、未关闭风险、暂停/退出手册和用户通知方案；重要资产/venue/合约改变须重新核验。
- [ ] M16.05 取得用户明确发布授权后才做受限主网上线；发布后的监控和扩容分别审批，不能自动启动做市、扩大资产列表或提高容量。

验收：有可核验的版本、部署清单、测试/审计、风险处置、法律准入和恢复证据，相关 High/Critical 问题关闭。独立审查不能由本项目开发者自己签作“独立”；服务能运行不代表产品已合法或所有风险为零。

这一关口使用 [NIST SSDF](https://csrc.nist.gov/pubs/sp/800/218/final) 的生命周期安全思路组织证据，不声称本计划是认证。安全测试贯穿每个模块，M16 负责最终整体验证，不是到此才开始考虑安全。
