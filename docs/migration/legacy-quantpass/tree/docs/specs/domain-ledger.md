# M02 本地资金领域模型

范围：TEST_ONLY，纯 TypeScript 状态转换；不连接钱包、链、交易场所、数据库或保密环境。依赖 M01 已通过的本地检查；远端 CI 权限仍阻塞，按用户“继续往后做”的授权推进本地模块，不将该阻塞标为解决。

## 数据与算术

示例结算单位 TEST_ONLY_USDT_UNIT 使用 6 位精度；这不是已核准链上 USDT 地址或精度。Pass fixture 使用整数数量，每枚对应 1 USDT 额度；不决定可拆分代币标准。金额保存为规范整数字符串，计算用 BigInt；最多 256 位是数据表示边界，不是策略容量承诺。

- idle：用户闲置余额，不用于订单或默认补亏损。
- activeCash：策略运行现金，其中已确认的 feeLiability 不可再交易/撤回分配。
- orders：各订单预留现金，从 activeCash 转入，不重复计入总资产。
- positionCost / positionValue：一个聚合测试持仓的成本/计价值，浮盈不记为闲置现金。
- pendingWithdrawals：已从闲置隔离、尚未确认到账的提款现金；确认后才增加 withdrawalsPaid，取消后返还闲置。
- feeLiability：现金支持的待支付测试费用；feesAccrued = feesPaid + feeLiability。

守恒：用户权益 = 存款 − 已付提款 + 已实现盈亏 + 未实现盈亏 − 已计提费用。权益同时等于闲置 + 运行现金 + 订单预留 + 持仓价值 + 待提款现金 − 费用负债。每次成功动作前后都验证；失败不修改原对象。

## 权限与重试

调用者身份由外层提供，领域模型不是登录系统。owner 可模拟存款、分配/撤回分配、申请/取消提款、启停和取消订单；指定 executor 可确认提款、记录预留/成交/估值/全量结算与费用支付。M03 必须在服务端认证测试会话并检查对象归属，不能将客户端传入 role 视为信任。

每个 Vault 的命令 id 唯一；同 id、相同请求与 actor 重试不重复记账，变更请求拒绝；新命令必须携带当前 expectedRevision。JSON 保存包含 receipts 和事件索引，恢复后仍能拒绝重放。领域函数本身不提供跨进程事务或防文件篡改证明，M03 的存储层必须负责原子性。

## 未决规则如何隔离

完整卖出需要调用者显式注入 TEST_ONLY SettlementPolicy，未注入直接拒绝。modules/M02/fixtures.ts 提供无费用、全量结算后超额归闲置的简化样例；不得作为生产默认、HWM、部分成交/跨 Vault 分配或缓冲耗尽规范。非零费用测试也是明确 fixture，不确定真实费率。租金不从这个用户账本扣除，Builder/平台的费用分账属于 M12/M13。

stop 只记录停止请求；仍有订单/持仓时为 stopping，不假装立即清仓。已有订单可能成交，需取消或等待结算；不再接受新的买入预留。分配检查使用当前运行净资产加新增分配与 SaaS 额度比较，浮盈超额不自动强卖；模拟交易记录不是生产价格/经济风险引擎。

## 尚未覆盖

真实 token 所有权、可拆分 Pass、多个资产仓位、部分成交、价格真实性、关联成交、链最终性/重组、跨 Vault 总容量、长期历史归档、HWM、公允调度和退出流动性尚未实现。最多 10,000 条模拟命令用于限制本地样例资源；不得将这类测试资源限制迁移为生产用户退出限制。存储恢复检查用于发现不一致，不证明对本机管理员的防篡改。
