# ADR-0001：单人开发工程基调

日期：2026-09-05。状态：实施采用。用户授权助手在总览项目后决定技术基调；此技术选择不批准 D1–D9。

## 决定与后续承接

| 边界 | 选择与原因 | 后续模块 / 不包含的权限 |
|---|---|---|
| 工程 | TypeScript、Node 24、npm 单仓库，使用锁文件 | 沿用原型，避免多套语言工具链；不会把 JS Number 用作资金金额 |
| Web | React + Vite，M03 按需建一个应用 | Builder/Consumer/市场复用组件与 API；不将私有策略或凭据打进前端包，不要求 SSR |
| API / 后台任务 | Fastify 模块化后端，M03 引入 | Indexer、Keeper、业绩、租费和市场保留逻辑模块；不会在此进程运行不受信策略 |
| 领域 | 无框架依赖的 TypeScript 纯规则模块，M02 实现 | 额度/账本与 HTTP/钱包/存储解耦；不把框架 DTO 当合约唯一规范 |
| 存储 | 一个主要关系数据库方向；数据库/驱动在 M03 依据事务、并发、迁移和恢复样例选定 | 不以简单 KV 或进程缓存假装持久化账本；不现在安装多套数据库 |
| 合约 / SDK | 独立 Solidity 工程与共享 schema、测试向量，M05/M06 落地 | 不沿用 Ed25519 作 EVM 规范，也不提前定 token 标准 |
| 保密运行 | 独立进程/运行环境/密钥域；M04 实验后再决定语言和保密栈 | 不要求量化代码必须用 TS；不能合并到持有应用权限的后端 |
| 测试 | 保留 node:test 单元与负向测试；E2E 在 M03 引入 | M01 不以生成静态 HTML 冒充业务前端或 E2E |

框架选择通过接口隔离降低后续变更成本，但不承诺永远不会重构。架构改变应有新的 ADR、受影响模块与迁移证据，不静默替换。

## 本轮依赖与工具约束

- Node 基线为本机已实测 24.12.0，npm 11.6.2；开发线限制为 Node 24 / npm 11，不代表该 patch 已通过生产安全审核。
- TypeScript 使用 6.0.3：原 7.0.2 超出当前 typescript-eslint 8.69.0 声明支持范围（>=4.8.4 <6.1.0）。这是兼容性选择，不追逐最新主版本；升级编译器需同时验证 lint/test。
- Node 类型对齐 24 主版本。精确依赖写入 package.json 与 package-lock.json；npm ci 用于复现。
- M01 只安装实际使用的检查工具；React/Vite/Fastify 在 M03 实际建应用时再锁定兼容版本，避免闲置运行依赖提前扩大维护范围。
- 默认禁止 npm lifecycle 安装脚本。未来需要 native build 的依赖必须单独审核脚本及权限，不能全局取消约束来通过构建。
- 格式化覆盖 JS/TS/JSON/YAML；Markdown 与 HTML 模板保留现有语义和布局，不让表格重排破坏看板解析。生成 HTML 不手改。

## 检查边界

Typecheck、lint、格式、单测、源码 secret 基线扫描和制品 hash 属于本地确定性检查。依赖漏洞查询依赖外部注册表，CI 单独强制运行；失败不能等同于“无漏洞”。自建 secret 扫描只覆盖常见模式和已跟踪/未忽略文本，不能保证检测所有私钥、助记词或二进制秘密；全面扫描与供应链审核仍须扩充。

M01 明确拒绝 testnet/production 启动；这比填一组假资产、假费率来模拟生产配置更符合当前未决状态。该检查工具尚未被真实 API/执行器消费，M03 必须把它接到每个启动入口。
