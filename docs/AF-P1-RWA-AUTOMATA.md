# AlphaForge RWA 第一阶段使用说明

本阶段提供本地合成行情 → 自动再平衡 → 风控清仓 → 账本记录 → 重启恢复的最小闭环。使用现有 Hackathon 工具链和 SQLite；不引入钱包、凭据、真实合约地址或外部交易。

## 启动与体验

在本分支独立 checkout 中用 fnm 激活 `.node-version`，按环境规范安装锁定依赖，然后运行 `npm run demo`。打开 `http://127.0.0.1:4180/automata.html`，或从产品导航的 RWA 模拟入口进入。

1. 选择 Alice 或 Bob，建立测试 Vault，存入 1,000 模拟资金。
2. 设置启动资金、股票代币权重、再平衡偏差、检查间隔、模拟交易费和滑点上限。
3. 选择上涨、下跌或流动性受阻行情。启动后配置固定，每秒推进一帧，共 120 帧；按钮可额外推进一帧。
4. 观察调整后收益率、单位净值曲线、持仓和成交记录。上涨行情默认配置会触发 +10% 上限并清空持仓。
5. 可暂停策略、继续策略、追加或撤回运行资金；暂停时风控继续检查。
6. 停止立即锁定全组合清仓。成功卖完后显示“已停止”；清仓现金可转回闲置余额，再建立下一次运行。

## 已确定的资金与风控规则

- 追加从当前 Vault 的闲置余额扣除，并受 Pass 额度约束。
- 撤回只使用 Bot 可用现金。请求 300、现金只有 200 时拒绝整笔请求并提示最多可撤回额，不卖出股票，不静默改为部分撤回。
- 用精确有理数份额调整资金进出。百分比阈值基于相对于启动单位净值的组合累计收益，资金追加、撤回不会被算作收益或亏损，也不会重置清仓基准。
- 百分比可设置上限、下限或两者；触碰即清仓全组合。指定资产的卖出报价触碰价格上下限，也清仓全组合。比较使用精确整数交叉乘法，页面显示舍入不决定触发。
- 清仓触发永久保留；价格回升、重复点击、进程重启都不能恢复买入。滑点、容量或报价阻止卖出时保留持仓并显示受阻原因，在下一帧重试。立即发起不等于保证立即成交。
- 完全平仓时沿用现有本地结算策略，超出 Pass 额度的现金自动归还闲置余额，并同步调整份额。展示累计归还金额；不把归还误算成亏损。
- 清仓中与已停止记录不能再变更运行资金；已停止的旧记录不能覆盖后来的 Vault 资金。
- 用户命令有幂等 ID；常规操作检查版本冲突。停止允许较旧版本，避免行情更新挡住清仓；未来版本仍拒绝。

## 实现边界

纯引擎位于 `packages/automata/src`，持久化与 Vault 投影位于 `apps/server/src/automata-store.ts`，接口和调度位于 `automata-routes.ts`。所有资金、运行状态和审计事件在同一个 SQLite 事务中提交；失败回滚。

`rwa-a`、`rwa-b` 是无合约地址的合成身份。核心/API 支持两个标的和组合清仓，首版页面只配置 RWA-A。参考股票价与可执行代币报价分开。当前策略为阈值再平衡；以后其他 Bot 可复用状态、资金和风控模型，但本版不是任意策略插件平台。

每次运行绑定引擎版本、配置和数据集摘要；报价顺序、重复、容量消耗都持久化。时间来自回放帧，服务离线不会跳过未处理帧。回放结束不伪装为已停止；本地虚拟时间停在末帧，可以用末帧报价手动清仓。不能把这一行为照搬到实时交易。

模拟场所同步返回成交或拒绝，没有外部在途订单。未来真实场所需要订单状态对账、未知结果恢复、链确认和重组处理。每账户最多 50 次历史运行；120 帧演示集以及有界命令记录用于第一阶段验收，不构成长周期生产容量承诺。

## 验证与证据

新增 29 个行为测试，覆盖上下限等值触发、多标的清仓、手续费/滑点、容量不足、恢复、重复请求、资金净值、权限、事务回滚、跨字段校验、停止并发及超额度结算。入口是 `npm run test:automata`，也接入 `npm test` 和管理检查。

开发期检查已通过：29 项专项测试、类型检查、ESLint、生产构建。浏览器验证了上限自动清仓、运行中追加/撤回和拒绝超额撤回。初次全量测试的来源摘要不一致通过保留原始来源并追加实际改动提交的方式处理，不改测试预期或历史 PASS。

最终源代码 C、真实检查清单 R、生成快照 S 分开提交；完整结果以 `.checks/management/latest.json` 和生成的管理快照为准。独立审查、托管多平台 CI 和真实链上验证未执行，不能以本地自查代替。当前用户要求单人执行，未启动其他代理。
