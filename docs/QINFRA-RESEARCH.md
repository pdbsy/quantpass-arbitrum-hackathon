# AlphaForge 回测、实时模拟盘和交易成本：研究与验证

路线选择：沿用现有执行内核。当前交付的是可运行的合成研究工具及验收测试，真实数据/实时连接/场所模型仍是后续研究；不把快速播放历史称为实时模拟盘。

## 运行与复现

```bash
npm run --silent research:quant > .checks/qinfra-research-report.json
npm run test:automata
```

报告含输入帧、策略标识、上游固定提交、引擎/模型/策略源码 SHA-256、参数、数据摘要、精确 Node 版本、时间与舍入规则、模型版本，以及完整信号/成交/权益检查点和结果摘要。manifestId 由这些输入确定；生成时的 checkout HEAD 与脏状态另列，不能把未提交代码伪称为该 HEAD 的实现。源码内容摘要覆盖执行用到的本地模块。

研究时将每个合成观察视为已结束周期：第 t 帧生成的目标，最早在第 t+1 帧执行。实际本地演示使用的是已观察、仍有效的 quote 协议，允许在该报价帧执行；两者具有不同成交时序，**不能直接比较收益并宣称引擎不一致**。未来历史 bar 和实时报价必须明确各自语义。

目前的自动验证：
- 20 次重复运行：全状态一致；JSON 中途检查点恢复后，信号、成交和账本一致。
- 相同有序事件异步输入：全状态一致。这只验证记录流等价性，不代表真实网络或多线程调度已经验证。
- 未来数据修改不影响过去前缀；第 31 周期的入场信号在第 32 周期才成交，成交价来自第 32 周期。
- 数据或成本参数变化会改变 manifestId。末尾未执行信号/持仓如实保留，不凭空添加末日成交。

## 成本模型验证

现有内核以 bid/ask 为基础，加费用、额外不利滑点和容量约束。研究报告分别给出 EMA 完整策略敏感性，以及固定交易路径敏感性，防止成交变化影响下一次信号而混淆成本比较。

固定路径示例：初始 1000，买入 5 单位于基准 100，卖出于基准 130，金额保留 6 位小数。每次成交的手续费/滑点设定与实际结果：

| 手续费 | 不利滑点 | 最终权益 |
|---|---|---|
| 0 bp | 0 bp | 1150.000000 |
| 10 bp | 0 bp | 1148.850000 |
| 10 bp | 25 bp | 1145.975375 |
| 10 bp | 50 bp | 1143.100750 |

报告中 grossPnl 是按模拟成交价计算、扣显式手续费前的损益，已经含执行价格变化；满足 `最终权益 = 初始权益 + grossPnl - fees`。它不等于无冲击参考价毛收益；本轮没有把价差、冲击、延迟拆成经过市场校准的独立归因。固定路径的成本单调结论不推广为所有策略路径的定理。

下一步研究分级：
1. 明确报价中的费用/价差是否已包含，避免再次扣减；支持成本逐笔明细、基准/压力情景。
2. 在拥有适当交易量/深度数据后，研究订单规模、可用深度、延迟、部分成交与拒单。
3. 针对实际 AMM/RFQ 场所研究储备/tick 报价、报价过期、路由费、Gas 和失败交易成本。最大滑点是拒绝边界，不是实际费用预测；没有数据支持时只标为假设情景。

Uniswap 官方区分由订单规模引起的价格影响和等待成交期间的价格变化：[交易与价格影响](https://developers.uniswap.org/docs/get-started/concepts/traders/swaps)。本轮未访问任何主网 RPC。

## 实时模拟盘的下一道研究门槛

需要先指定目标链、发行方、股票代币和交易场所，再选择报价来源。

- 股票参考行情与代币可执行报价是两条数据通道；只有股票数据时标为代理模拟。
- 先做只读采集与录制，记录事件时间、接收时间、排序与质量标记；基于录制流对齐研究回放。
- 再验证断线、过期、重复/乱序、控制器故障与重启，且风控不依赖策略进程存活。停止受流动性阻碍时公开显示未完成清仓。
- 现有 120 帧、run 命令和 Vault 历史上限继续生效。持续运行需要独立设计持久事件日志、快照与归档，不通过简单移除上限或丢弃审计实现。

真实历史数据还需确定时区/交易日历、拆股分红、点时可用性、退市与缺失数据政策。Alpaca 文档区分 IEX、SIP 和延迟源，不能依赖隐式默认来声称全市场实时数据：[行情说明](https://docs.alpaca.markets/us/docs/real-time-stock-pricing-data)。未开通或存储任何数据服务凭证。

## 备选框架保留为对照

用户选择 A；LEAN 和 Nautilus 没有安装或接管底座。未来可以独立用固定数据做交叉核对，但需明确不同的舍入、成交和时间规则。LEAN 官方纸面交易默认模型不含滑点且市价单即时完整成交，不能直接充当 RWA 流动性模型：[纸面交易](https://www.quantconnect.com/docs/v2/cloud-platform/live-trading/brokerages/quantconnect-paper-trading)。Nautilus 的共同核心可供后续评估，仍需验证连接器与恢复行为：[架构说明](https://nautilustrader.io/docs/latest/concepts/backtesting/)。
