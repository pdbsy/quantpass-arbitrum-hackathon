QUALITY BAR

工程统一标准

Ready 与 Done 分离

强制安全边界

  • 默认拒绝：未识别网络、缺失配置、证据不完整或状态不确定时停止写操作。
  • 非托管优先：应用不得持有用户助记词、私钥，也不得获得提现或任意转账能力。
  • 测试网隔离：Chain ID 必须从配置、钱包与 RPC 三方核对为 46630。
  • 真实性：模拟、本地、测试网和未实现能力必须在界面与文档中明确区分。
  • 主网关闭：不存在可由单一环境变量或隐藏按钮绕过的主网写入路径。

Definition of Ready

  1. 目标、范围、依赖和信任边界清楚，未决策项已登记。
  2. 至少三个可验证验收条件，包含失败关闭或负向场景。
  3. 已明确测试方法、证据位置和停用或回滚路径。
  4. 所有前置依赖为完成状态，且没有未接受的 Critical/High 阻塞项。

Definition of Done

  1. 实现、正向测试、负向测试和边界测试全部通过；关键授权与会计路径分支覆盖 100%。
  2. 总体自动化覆盖率达到约定阈值（目标不低于 90%），fuzz/invariant 运行参数与种子可复现。
  3. 威胁模型、README、接口和运维文档同步；无未说明的 Critical/High 风险。
  4. 从干净检出可复现构建，CI 全绿，依赖、secret、license 与静态分析门禁通过。
  5. 至少一次独立复核，并记录提交、报告、哈希、交易或浏览器链接等验收证据。
  6. feature flag、暂停、降级、迁移或停用路径已演练，不把“可升级”误当作回滚。

安全原则

  • 最小权限与职责分离：用户、策略运行时、风险签名者、快照签名者、暂停者和部署者分别建模；无权限 relayer 不构成授权角色。
  • 精确会计：链上金额使用整数，显式处理 decimals、舍入、手续费代币与异常 ERC-20。
  • 签名有域：授权必须绑定 chainId、verifyingContract、账户、nonce、deadline 与具体 calldata。
  • 幂等与可恢复：交易提交、替换、掉线、重组和重复回调都必须得到确定结果。
  • 证据优先：完成状态只由可复现测试、哈希、交易和独立复核证据支撑。
  • 供应链可追溯：工具链、依赖、Actions、ABI、字节码与部署参数全部固定并可重建。
  • 无秘密进入仓库：密钥不写日志、不进浏览器存储、不进入示例文件或构建产物。
  • 可停用而非假回滚：不可升级合约发生问题时暂停新入口、保留安全退出并迁移到新地址。
