# Source coverage qualification and current acceptance

The versioned entrypoints use the qualified, isolated Istanbul instrumenter 6.0.3 graph and Node 24.21.0. `planning/coverage-toolchain.lock.json` binds tool sources, licenses, archives and every installed file. The complete installed-file inventory is stored in three SHA-256-bound chunks so each remains within the existing public-metadata scanner budget; no entry is omitted and the scanner limits are unchanged. The root product dependency graph is unchanged. The optional qualified suites fail when their explicit tool prerequisite is missing; they are not silently skipped or substituted by an ordinary unit-test PASS.

`npm run coverage:qualify` requires `AF_QUALIFIED_COVERAGE_TOOLS` pointing to the verified isolated `node_modules`. `npm run coverage:prepare -- --tools <directory> --base <40-character-SHA>` freezes a clean Git candidate, complete executable-source inventory, canonical generated-alias proof, zero-count graphs, original TypeScript and inline-prototype coordinates, exact generated code and source maps. Hidden index flags, replacement refs and shallow history are rejected. Source graphs are regenerated during replay, not trusted merely because a report carries its own checksum.

`npm run coverage:node -- --tools <directory> --base <40-character-SHA>` runs the real `npm run check` through the bounded local executor and the source-bound Node hook. Each attempt has a unique ignored output directory. The hook also instruments its own generated bootstrap and the first-party workflow launcher. Every lifecycle has a start; complete matching artifacts contribute measured hits, while unflushed starts contribute zero with the full static denominator retained. Unknown/corrupt/mismatched observations fail validation. Root workflow completion, actual exit status, process cleanup and log integrity are independently checked before functional PASS. Logs and failed attempts remain available.

The replay report preserves four separate Istanbul dimensions, per-file missing lines and branch locations, commands, exact source/tree/base, tool/config digests and raw lifecycle inputs. Node-only execution is explicitly labeled NODE_WORKFLOW_ONLY. Passing that command means the actual Node workflow succeeded; it does not mean coverage thresholds, browser/API/chain acceptance, hosted checks or independent review passed. Until normative dimension interpretation is independently closed, the report conservatively evaluates the frozen 90 percent target against all four dimensions. Critical permission/accounting semantic cases require their own accepted assertions; Istanbul branch coverage is not MC/DC or proof of every optional-chain outcome.
