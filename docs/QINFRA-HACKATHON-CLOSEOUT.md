# AlphaForge Hackathon 量化底座收口

本次按用户选择的方案 A，沿用已有底座，部署开源 EMA 适配版作为测试策略。这里的部署只指回环地址的 local/mock 服务，不代表云服务、链上部署或真实交易。

## 一键运行

先在当前独立 checkout 中激活 `.node-version`，使用已批准 Node 24.21.0 / npm 11.19.1 和已锁定依赖：

```bash
npm run demo:ema
```

打开 `http://127.0.0.1:4180/automata.html`，选择 Alice。服务建立独立 `.data/qinfra-ema.sqlite` 模拟账本和 `.data/qinfra-ema-outbox.sqlite` 请求日志，不复用普通 `npm run demo` 的数据。首次存入 1000 模拟资金、分配 500，A/B 各 50% 预算。重复启动恢复相同 run，不重复充值或重置持仓。若 4180 已被其他服务占用，启动报错，不接管该进程。

快速演示可运行 `npm run demo:ema -- --fast`，仅将墙钟推进间隔从 1000ms 改为 20ms，不改变输入时间戳或策略周期。固定 120 个合成观察周期，先横盘、再上涨、后下跌。EMA 预热后开仓，反向交叉时平仓；回放末尾控制器通过正常 stop API 结束运行，服务保留供页面检查。底座将这个 API 停止记录为 manual；不表示用户一定点击过按钮。

**完成后的再次启动只展示已完成运行。** 不自动清除历史来“重演”。自动化验收通过临时隔离账本创建全新运行；已保存的演示账本可以通过现有备份方式保留，但不要删除证据来获得绿灯。

Ctrl-C 关闭服务和控制器。进程退出本身不等于已清仓；下次启动从持久状态恢复。在运行页面点击停止会立即进入底座清仓路径；报价不可用或容量不足时保留受阻状态，不伪造成交。暂停不提交策略信号，行情与风险检查继续推进。演示服务器只自动推进固定 `qinfra-ema-demo`，新建的其他运行须手动推进或用普通演示服务器。

## 策略来源与改动

上游为 QuantConnect/Lean 的 `MovingAverageCrossAlgorithm.py`，固定 commit `ebd7268d68609ae85f73de8290d9673afb1992ac`，Apache-2.0。原始 Python 和许可证完整保留在 [来源目录](../third_party/lean-ema/README.md)，不会作为脚本执行，也未安装 LEAN。

适配版采用 15/30 EMA、慢线预热和原入场容差 0.00015，持仓时快线低于慢线退出。与上游不同：这里使用明确标记的合成周期、两个资产预算、固定点数值舍入与目标仓位协议。默认 50% 上限和 -20% 下限仍由底座管理；策略不能覆盖暂停/停止或调整风控参数。这不是上游日线策略的收益复现。

`GET /strategy-context` 现在包含已观察的 `observations` 前缀，最多 120 帧，不返回未来帧。EMA 可以从该前缀重建指标，不依赖客户端易丢失的内存状态。旧三类数据集的内容与哈希保持不变。

## 请求恢复

EMA 客户端在发出决策前，先用同步 SQLite 持久化完整 JSON 请求。重启后先重试原 ID/原请求，再计算新目标。日志按 origin/owner/run 隔离，Cookie 不写入日志。服务器的持久幂等回执确保响应丢失后也不会重复成交。

确定性的帧/版本冲突可以读取新状态后重新决策；磁盘写入失败会阻止发送。outbox 不是通用消息平台，演示按单控制器部署，不宣称多实例主从切换。正常关闭会关闭数据库；突然退出由 SQLite 保留已提交记录。

## 验收与边界

新增验收覆盖 EMA 预热/双向信号、未知未来帧拒绝、真实 API 账户隔离、已成交响应丢失后重启、写盘失败不能跳过持久化、重复部署不重复充值、暂停继续风险行情，以及研究回放下一事件成交和复现。所有测试均注册到 `npm test`、`npm run test:automata` 与管理采集器。

本地浏览器已观察到两笔买入、两笔卖出，A/B 持仓归零，120 帧后 stopped。页面给出固定上游链接、最近信号和成交记录。此为执行闭环验收，不是策略盈利证明。

最终准确源的 PASS 以 C/R/S 生成证据和实际命令退出码为准。之前第二阶段尚未公开推送；GitHub 推送、草稿 PR、远端 CI 和最终合并状态必须据实际操作分别报告，不能由本地绿灯替代。自动审批此前要求对公开仓库发布明确授权，未通过其他途径绕过。
